# 小鲸鱼计费名片

把开源挂件 [DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)
的"看余额"体验搬到 FoloToy AI Passport 上:一张名片,开机就能看到 DeepSeek 账户还剩多少钱、
今天花了多少、现在是不是错峰时段。

界面是应用自己画的三屏(挂件 / 菜单 / 配网),不复用基线 demo 的测试菜单与像素外壳;
角色本体直接嵌入参考挂件的原版资源 `DSniang1.png`(缩成 139 × 139 的 RGB565A8 C 数组,
经 `tools/gen_whale_img.py` 生成,不是本项目自生成的图片);音效全部由代码合成,**没有音频文件**。

视觉与交互对齐开源挂件:泡泡与 `assets/DSniang02.png` 同款 —— **白底 + `#203170` 粗描边的
大椭圆**,底下挂一条斜 10° 的半椭圆尾巴和两颗依次变小的小椭圆泡泡,泡泡内是**居中三行**
(标签 / 主数值 / 补充),主色与文字色全部取挂件样式表里的 `#203170`、`#536BA9`、`#9FB0D9`。交互以**长按为主** —— 挂件在手机端是"长按鲸鱼 1.5 秒唤出菜单",
名片就把长按确定键做成同一件事。

### 角色图

主屏鲸鱼区的角色直接使用参考挂件的原版资源 `assets/img/DSniang1.png`(610 × 610 透明底
cut-out,出处见挂件仓库的 PROVENANCE 说明 —— 挂件作者用 AI 工具生成后人工挑选裁切,
本项目原样引用,**不是本项目自生成的图片**):

- `tools/gen_whale_img.py` 把原图裁掉透明边距后等比缩成 139 × 139,编码为
  **RGB565A8** C 数组(`assets/img/whale_dsnang_img.c`):前 139 × 139 × 2 字节小端
  RGB565 颜色面,紧跟 139 × 139 字节 A8 透明度面,边缘抗锯齿保留 8 bit 全量 alpha;
- 位置:**靠右**(横向 95..234,离右边框 6 px)、底边压在正常腰线 262,与状态行
  (266 起)留 4 px 净空;左侧空档留给消费时的金币掉落;
  Q 弹时随舞台一起缩放(舞台里只有角色,气泡是独立的一层,不跟着弹);
- 消费时金币仍会掉落,落点改在角色左侧空档(`COIN_X`),免得落在脸上;
- 需要换图/改尺寸时改 `tools/gen_whale_img.py --size N` 重新生成即可,生成脚本还带
  `--ascii` 预览,不刷机也能先肉眼校验轮廓。
- **LVGL 改用系统堆分配**(`sdkconfig.defaults` 的 `CONFIG_LV_USE_CLIB_MALLOC=y`):
  LVGL 自带 TLSF 静态池(96 KB 时)在角色图 + 气泡图同时上屏后会**死循环**在
  `lv_tlsf.c` 的 `block_locate_free`,表现是开机后 main 任务被任务看门狗每 5 s
  报警、界面完全卡死。池不够就死循环,扩容只是治标(48→96 撑过一版又爆),
  改走系统堆后余量更大、不足时返回 NULL 而非死循环。改 defaults 记得删
  `build/validation-whale/sdkconfig` 才生效。

### Q 弹动画(squash & stretch)

原来的"轻微上下浮动"改成了与参考挂件一致的 **Q 弹**;**只有角色在弹,气泡不参与**:

- 权威参数来自参考挂件:`.dshwv-body{transform-origin:50% 100%;transition:transform
  .22s cubic-bezier(.34,1.56,.64,1)}`,按压态 `scaleY(.88) scaleX(1.05)`;
- 一次 Q 弹 = 压扁 180 ms(ease-out,`scaleY → .88`)→ 弹回 420 ms
  (`cubic-bezier(.34,1.56,.64,1)`,值会过冲到 1.05 再收住,这就是"Q"的手感);
- `scaleX` 与 `scaleY` 互补:`sx - 1 = 5/12 × (1 - sy)`,压得越扁越往外撑,
  与参考 `.88 ↔ 1.05` 这对数值一致;
- **舞台里只有角色**:`stage` 是 y 123..262(240 × 139),以**角色脚底中心**
  (120, 262)为原点缩放。气泡是独立的一层,不跟着弹 —— 实测气泡跟着缩会晃得厉害,
  而且舞台一变大每帧要重绘整屏,SPI 屏刷新跟不上直接卡成幻灯片;
- **整体放慢的原因**:参考给的 .22s 是按 60 fps 网页定的,照搬到名片上 110 ms 只够
  出两三帧,看着就是"闪一下"+ 卡顿。压 180 + 回弹 420(约 0.6 s)后每帧位移更小,
  视觉上才连贯;
- 常驻一条幅度更小的呼吸(半周期 2.4 s,只压到 `.97`);按键时先掐掉呼吸再播完整
  Q 弹,回弹结束把呼吸接回去;
- 顶栏电量、状态行、底部提示、气泡层都留在舞台外,不跟着晃。

### 气泡进出场

气泡不再硬切,整层(气泡图 + 三行文本)走**缓进缓出**,方向固定是「下进下出」:

- 消失:**由上至下**,一边往下沉一边淡出(走到下方 32 px),300 ms;
- 出现:**由下至上**,从下方 32 px 浮到位一边淡入(`opa 0 → 255`),340 ms;
- **切换内容**(上下键换视图)是把两段串起来:旧的先由上至下沉下去消失 →
  趁气泡全透明把三行字换成新的 → 新的再由下至上浮出来;
- 换字放在消失动画的完成回调里,否则会看见旧字在半透明状态上直接跳成新字;
- 收起时飘完才真正 `HIDDEN`(否则最后一帧会被掐掉);切换时 `s_bub_shown` 仍是 true,
  不隐藏,由入场动画直接接管;
- 路径统一 `lv_anim_path_ease_in_out`;opa 只设在层上就够:LVGL 9 的 opa 会递归
  作用到子对象,图像与三行文本一起变;
- 状态没变不重播:开合只有 `bubble_open` 翻转才起动画,切换只有 view 变化才起动画
  (余额每秒刷一次 `whale_ui_update`,两者都没变时直接写文本);
- 三行文本归气泡层,收起气泡时一起消失(之前挂在舞台上会留下三行孤字)。

相关常量(`main/whale_ui.c`):`BUB_OUT_MS` 300 / `BUB_IN_MS` 340 / `BUB_SLIDE_DY` 32。

### 气泡(对话泡泡)

气泡不再是 LVGL 圆角矩形拼的"胶囊",而是照参考挂件的气泡 SVG 几何(画布 1026 × 700、
描边 `#203170` 宽 18)整条 raster 成一张 **RGB565A8** 图(`assets/img/whale_bubble_img.c`,
由 `tools/gen_whale_bubble.py` 生成):

- 大椭圆:中心 (454,247) rx373 ry232 → 屏幕上 194 × 120,落在 18..212 / 30..151;
- 尾巴:半椭圆连接大椭圆底与小气泡1,倾 10°;
- 小气泡1 (352,561) rx37.5 ry26、小气泡2 (442,646) rx24.5 ry18,等比缩放后落在
  大椭圆左下方 —— 与 `assets/DSniang02.png` 的构图一致;
- 叠放次序照参考:角色先画、气泡压在上面(挂件里 bubble 带 `z-index:1`);
- 三行文本按椭圆中心排版(行心 ±32,文本宽 140):扁椭圆越靠上下越窄,140 是
  不压到描边的最大宽度;超长内容(SSSID 等)仍用省略号截断;
- 改尺寸/位置:重跑 `tools/gen_whale_bubble.py --width N`,再同步 `whale_ui.c` 里的
  `BUB_IMG_*` 与 `BUB_ELL_*` 常量;`tools/preview_whale_screen.py` 会用同一套几何
  出整屏预览,先看图再刷机。

### 熄屏策略

菜单里「熄屏时间」决定空闲多久熄屏,默认是 300 秒(5 分钟);任意按键都会把空闲计时清零。

| 档位 | 背光调暗 | 转入深睡 | 说明 |
| --- | --- | --- | --- |
| 关闭 | 不调暗 | 不休眠 | **屏幕一直亮着**,Wi-Fi 也保持连接,余额照常自动刷新 |
| 100 秒 | 50 秒 | 100 秒 | |
| 300 秒(默认) | 150 秒 | 300 秒 | |
| 30 分钟 | 15 分钟 | 30 分钟 | |

几点说明:

- **先半程调暗、到点再睡**:到一半时间先把背光压到 8%,给人一个"快睡了"的提示;
  中途碰任意键立刻恢复满亮度并重新计时
- **「关闭」是耗电档**:不休眠意味着屏幕和 Wi-Fi 一直开着,只适合演示、调试这类需要长时间
  看着屏幕的场合;日常用建议留一个有限档位
- **配网/取余额进行中不睡**:用户正在读屏幕上的热点信息,或正在等余额回来,这时就算到了点
  也不睡(判据是 `s_busy` 与 `whale_prov_running()`)
- 唤醒方式不变:深睡后按任意键唤醒,醒来重新连网并刷一次余额

## 配网网页(唯一的文本输入通道)

三颗按键没法输入 API Key,所以配网走网页:

1. 设置页 →「配网与 API Key」→ 名片自建热点 `WhaleCard-<MAC 后两位>`,口令 `12345678`(`main/whale_prov.c`);
   进去时会先扫一轮附近热点,所以第一次打开表单就有列表
2. 手机/电脑连上热点,浏览器打开 `http://192.168.4.1`
3. Wi-Fi 名称是**原生 `<select>` 下拉框**:第一行是已保存的网络(默认选中),下面按信号强弱列出扫到的
   热点,每条标签是 `名称 · -48dBm · 需要密码/开放`;列表过时点页面上的「重新扫描附近热点」重扫一遍
4. 下拉里没有的网络(不广播名称的隐藏网络)改用下面的「手写 Wi-Fi 名称」输入框 —— 手写框非空时**优先**
   于下拉框;两者都没给就保留原来的 SSID,不会把已配好的网络冲掉
5. 填写 Wi-Fi 密码、DeepSeek API Key、刷新间隔,提交
6. 名片保存后立即尝试连网:连上会响一声,配网页显示 IP,然后自动回到挂件页(也可长按确定键手动返回)

扫描的细节和取舍:

- 最多取 48 条原始结果,去重同名 SSID(保留信号最强的那条),按信号从强到弱列前 12 个
- 同步扫描(`esp_wifi_scan_start(..., true)`),热点起来后就在自己任务里跑完,页面不需要 JS
- SSID 是用户文本,一律走 `whale_html_escape` 再进 HTML(`& < > " '` → 实体),否则特殊字符会破页面
- 扫描期间 Wi-Fi STA 会短暂暂停;配网阶段可接受,退出配网后不再扫
- **`<select>` 而不是 `<input list="...">`**:datalist 在手机上表现极不一致,iOS Safari 与各家 App
  内置浏览器常常根本不弹候选,用户看到的就是一个空输入框,以为没法选。原生 select 由系统画选择器,
  一定能点开;代价是不能边输边过滤,所以补一个手写输入框兜隐藏网络。`<option>` 的 label 里必须重复
  一遍 SSID 本身(只写 `‑48dBm` 的话,下拉收起后看不出自己选了哪张网)

页面同时注册了 `/generate_204`、`/hotspot-detect.html` 等常见联网探测地址并 302 回表单页,
让手机能自动弹出配网窗口(尽力而为,不做强制门户劫持)。

### 排障:网页返回 "Header fields are too long"

这是 httpd 的 431:请求头总长超过了 `CONFIG_HTTPD_MAX_REQ_HDR_LEN`。
手机/PC 浏览器一次会带上 User-Agent、Accept*、Accept-Language、`sec-ch-ua*` 等一大串,
**512 B 的默认预算必然超**。本应用已在 `sdkconfig.defaults` 里把它调到 2048 B
(`HTTPD_PURGE_BUF_LEN` 同时提到 64);改完必须重编,sdkconfig 一旦生成就不会自动重读
defaults —— 需要删除 build/validation-whale/sdkconfig 后重新构建。

### 排障:深度睡眠后 COM 口消失

ESP32-C3 的 USB-Serial/JTAG 在 deep sleep 时断电,串口会从系统里消失
(`Could not open COM3`)。按一下名片上的任意按键唤醒,或重新插拔 USB 即可;
`E:/Workbuddy/MPD/esp/flash_when_awake.py` 就是用来"等端口回来再刷"的。

## 数据与记账口径

- 数据源:`GET https://api.deepseek.com/user/balance`,请求头 `Authorization: Bearer <key>`,
  证书校验用 IDF 自带的根证书包(`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE`)
- 刷新间隔:30 / 60 / 120 / 300 秒,默认 60 秒;已连接时自动刷新,**长按上键**手动刷新
- 记账(与开源挂件一致):余额**下降**按观测累计为消费,余额**上升**记为充值、不冲抵消费;
  跨日(北京时间)以当日首次观测重建基线。账本存 NVS,掉电不丢
- 峰谷:工作日 09:00–12:00、14:00–18:00 为峰时,其余谷时;周末全天谷时

### 余额滚动动画

挂件里余额变化是数字滚动。名片上没有逐位翻牌的部件,这里用**数值补间**近似:
每帧把当前值格式化成 `¥x.xx` 重画,整数与两位小数一起动,600 ms ease-out 收尾。

几条边界:

- **首次拿到余额不滚** —— 从"没有"跳到"有"没有起点可补;断线重连后同理
- **切到别的泡泡视图立刻停滚** —— 主数值那行要让给别的视图内容,动画继续跑会覆盖它
- **超过约 2147 万元直接落值** —— `lv_anim` 的值是 `int32`,补间前先判范围
- 收尾回调会补最后一帧:补间的末帧不一定正好落在终值上,免得余额差一分钱

### 峰谷显示样式

同一份峰谷判定,换一套称呼 —— 对齐挂件峰谷模块的「显示样式」下拉
(`BUBBLE_PEAK_STYLE_OPTS`)。菜单 →「峰谷样式」短按确定键循环:

| 样式 | 峰 | 谷 | 泡泡标签 |
| --- | --- | --- | --- |
| 默认 | 高峰时段 | 空闲时段 | 峰谷时段 |
| 梁文峰谷 | 梁文峰 | 梁文谷 | 峰谷时段 |
| !?强强?! | !?峰峰?! | !?谷谷?! | 峰谷时段 |
| 倒计时 | — | — | 时段倒计时 |
| 简洁 | 峰 | 谷 | 峰谷时段 |

倒计时样式是特例:主数值直接显倒计时(`H:MM`,当天不再切换显 `--:--`),
补充行说明切到哪个时段 —— 对应挂件里那个独立的「时段倒计时」模块。
其余样式的补充行都是倒计时。

状态行左侧的峰/谷徽章**不随样式变**(始终「峰时 / 谷时」):那一格只有 44 px,
换成「空闲时段」这类四字文案会挤掉状态文案。
- 时间:连网后 SNTP 授时(`CST-8`)。授时失败时峰谷显示为"时间未同步",余额照常显示
- 预算 / 预警:阈值 0 表示未设置(一律不触发);越过阈值时响一次、状态行改文案,
  **回落后再越过才会再响**,不会每次自动刷新都重响一遍
- 配置结构变长时 `whale_store.c` 会认一次旧版 blob 并按字段迁移,**不会逼用户重新配网**

## 声音

`main/whale_tone.c` 用相位累加 + 256 点正弦表 + 包络合成 16 kHz 单声道 PCM。
音色取自挂件的 `assets/*.wav|mp3`:用 `tools/analyze_wav.py`(纯标准库)量出原音的
RMS 包络与零穿越率轨迹,再落到音符表里。挂件是取样音色,名片是合成复刻,
**只能做到"听感同族",不是逐采样还原**。

| 音效 | 触发 | 形态 |
| --- | --- | --- |
| 按压「呀」 | 挂件页短按 / 任意长按 | 方波 560→1240→900 Hz 上滑再落,约 0.16 s(挂件 `Ya1.mp3`) |
| 松开 | (保留,供后续扩展) | 方波 900→520 Hz 下滑,约 0.12 s(挂件 `Ya2.mp3`) |
| 金币掉落 | 检测到余额下降(消费) | 方波 B5 → E6,快速衰减,约 0.49 s |
| 经验球 | 试听 / 任务结束 | 方波三记上行 pluck 1760/2349/3136 Hz,约 0.29 s(`minecraft-exp-orb.wav`) |
| 钟声 A | 试听 / 任务结束 | 正弦 E6 起音 → B5 长延音,约 0.37 s(`task-end-a.wav`) |
| 连接成功 | Wi-Fi 拿到 IP | 正弦 C5-E5-G5-C6 上行琶音,约 0.54 s |
| 轻提示 | 切换菜单项 | 单声短音 |
| 预警 | 触达预算 / 余额低于预警线 | 两声等高 880 Hz,约 0.28 s |

### 第 21 版固件(修复「卡通小人不动」回归,sha256 `afe1b07d…ef8f`)

**根因是两个动画共用了同一个 exec_cb,被无差别删除:**

- `lv_anim_delete(var, exec_cb)` 是按 exec_cb **精确匹配**删除的;
- 而 **`lv_anim_delete()` 删除动画时不会调用 `completed_cb`**。

press 段被删 → 它的完成回调不跑 → **back(回弹)段永远不启动** → 回弹的完成回调也不跑 →

### 第 23 版固件(失败分级 · 差异化重连,sha256 `3832a2a9…fc09`)

反馈:DeepSeek 服务繁忙时,屏幕一直显示**「网络不可用」** —— 既与事实不符(路由
是好的),也没告诉用户该怎么办。查下来是三个结构性问题叠在一起。

**原来怎么写错的**:`WHALE_ST_NETWORK_FAILED` 一个枚举兜了 6 个写入点,连文案都
是同一句。其中 `http_status != 200` 这一支把 **429 限流与 5xx 全部算成"网络不通"**
—— 服务端繁忙走的就是这条。而失败一经写入就被钉住:

- `s_ui.status` 是单值槽,没有过期时间也没有失败计数,只有下一次成功才能翻回去;
- 自动刷新想重来还得等满一个 `refresh_sec`(默认 60 s),失败**不会**触发更快重试;
- 更要紧的是轮询条件写的是 `whale_net_state() == WHALE_NET_CONNECTED` ——
  **Wi-Fi 一掉线,连重试都不跑了**,状态行直接钉死成"网络不可用",只剩按键或重启。

| 改动 | 说明 |
| --- | --- |
| 状态分级 | 拆成 `NET_UNREACHABLE`(真网络故障)/ `SERVER_BUSY`(429·5xx)/ `DATA_ERROR`(返回体异常),各自对应不同处置:查路由 / 等对方恢复 / 兼容性告警 |
| 新增 `WHALE_ST_STALE` | 偶发失败的温和态,文案「稍后重试 · 12:34」;不说"故障",也不让屏幕跳红字 |
| 连续失败才升级 | `FAIL_REPORT_STREAK = 2`:第 2 次失败才升级到严重态,单次抖动全程静默 |
| 余额降级保留 | 失败时 `has_balance` 不清,旧余额照显 —— 一份旧数据比一句错误有用 |
| 新增 `updated_ok` 字段 | 记最后一次「真正取到余额」的时刻(`updated` 是当前时钟,每次 publish 都在刷),供 STALE 态显示数据新鲜度 |
| 指数退避 | 失败后按 15→30→60→120→300 s 递增重试,不再按原刷新间隔猛撞已繁忙的服务端 |
| **Wi-Fi 断线自动重连** | 轮询条件从"必须已连接"改成"未连接就 `connect_and_refresh()`",修掉上面的钉死问题 |
| 401/403 不参与计数 | Key 无效是永久错误,退避重试没意义,照旧立即明说 |

状态机的完整形态:

```
                ┌───────────── 成功 → ONLINE(streak=0, 记 updated_ok)
                │
取数 ──失败──→ streak=1 → STALE「稍后重试 · 12:34」(余额仍显示旧值)
                │
                └── 再失败 → streak≥2 → NET_UNREACHABLE / SERVER_BUSY / DATA_ERROR
                                         ↑
                                    退避 15→30→60→…→300 s 后重试
```

新增字模：稍/服/务/繁/忙/异/常 + 摸/头(第 24 版),字表 163 → 172 个非 ASCII 码位,267 glyph。

app 体积 1,780,432 B,分区余 78%;门禁 `verify_firmware` / `check_repo`(375 文件)/

### 第 26 版固件(区分"网络问题"与"API 问题",sha256 `ddd63e50…0268`)

反馈:**API 不对的时候,下面显示的还是"网络不可用"**。

查下来不是分级没做(第 23 版已经分了 429/5xx/JSON),而是**判定顺序错了**。

`whale_net_fetch_balance()` **即使自己返回了错误码,也已经把服务端给的 HTTP 状态码
填进了 `result.http_status`**。而旧代码第一条分支就是

```c
if (err != ESP_OK) { → 一律 NET_UNREACHABLE → "网络不可用" }
```

于是出现这种错案:**服务端明明回了 401 / 429 / 5xx**,只是流式响应中途断流导致
`esp_http_client_perform()` 报错 → 状态码被完全无视 → 屏幕谎称"网络不可用"。
用户的 Wi-Fi 好好的,却被指引去查路由器 —— 正是这次反馈的来源。

**修法:把「服务端有没有回话」提到最前面。**

```
① status ∈ [400,500) 且 ≠ 429  → AUTH_FAILED     Key 无效,请配网   (立即,不计数)
② status = 429 或 ≥ 500        → SERVER_BUSY     服务器繁忙 · 稍后
③ err ≠ OK 且 Wi-Fi 已掉线     → NET_UNREACHABLE 网络不可用 · 重试
④ err ≠ OK 但 Wi-Fi 还在       → API_TIMEOUT     未同步 · 重试     ← 新增
⑤ status 既非 200 也非上面几类 → API_TIMEOUT     未同步 · 重试
```

③④这一刀是这次的关键:**同一个"请求没成",用 Wi-Fi 是否还在来定性** ——
链路真断了才说"网络不可用";链路通的、只是对方没答完,只报"未同步",不冤枉本地网络。

新增 `WHALE_ST_API_TIMEOUT`(文案「未同步 · 重试」,103.12 px / 154 px 预算内,够宽)。
「未/同/步」三个字本来就在字表里,**无需重铸字模**。

另外把请求侧 4xx 从"仅 401/403"放宽到 **4xx 整体(429 除外)**,让 400(参数)、
402(账户没钱)也走"Key 无效,请配网"这条指回配网页的路径 —— 它们同样是"怎么重试都没用"
的永久错误,不该混进"服务器繁忙"。

app 体积 1,780,992 B,分区仍余 78%;门禁 `verify_firmware` / `check_repo`(375 文件)/
字体覆盖(172 字)全 PASS。

**已刷入 COM4**,写入 6.8 s,Hash verified。真机观察到:

```
W (44029) whale_net: Wi-Fi 断开,第 1 次重连      ← 自动重连确实在跑(第 23 版加的)
I (127359) whale_net: 已连接 Wi-Fi,IP=<本机内网地址>
I (131485) whale_net: 余额请求完成: HTTP 200, 135 字节   ← 取余额成功
```

⚠️ **刷后第一次上电的串口里出现过一次 `Load access fault` panic**,之后再没复现:
连续监听 90 s + 150 s、外加 3 次复位启动均干净(BAD=0)。从代码路径看它与本版改动
无关 —— 未配网时 `whale_config_ready()` 会提前返回,根本走不到这次改的 HTTP 分层,
且事后余额请求正常返回 200。推测是整片擦写后 NVS 处于全 0xFF 状态时的偶发。
