# DeepSeek Balance Whale Card

An AI Passport port of the open-source widget
[DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget):
a business-card-sized device that shows how much credit a DeepSeek account has
left, what today has cost, and whether the current tariff window is peak or
off-peak.

The application draws its own three screens (home / settings / provisioning) and
does not reuse the baseline demo menu or its pixel shell. The character itself is
the widget's original asset `DSniang1.png`, embedded as a 139 x 139 RGB565A8 C
array produced by `tools/gen_whale_img.py` (a scaled copy of the library asset,
not an image generated by this project); every cue is synthesized in code —
**no audio files**.

## Screens and controls

Portrait 240 x 320; content stays within x = 18..222 because the BSP masks the
screen corners with a radius of 30.

The visuals mirror the widget — same style as the widget's `assets/DSniang02.png`:
a **large white ellipse with a thick `#203170` outline**, a tilted half-ellipse tail and
two shrinking small ellipse bubbles below it; the text is **three centred rows**
(label / main value / hint) using the widget's own `#203170`, `#536BA9` and `#9FB0D9`. **Long press is the primary gesture** — the widget opens its menu from a
~1.5 s long press on the whale, and the card does the same from a long press on OK.

| Area | Content |
| --- | --- |
| Title bar | `Whale metered card` on the left, battery block on the right (percentage plus battery icon, `--` when unavailable) |
| Bubble | A **true ellipse** (194 x 120) with a blue outline plus a half-ellipse tail and two small ellipse bubbles, rendered as one image; three centred text rows |
| Whale | The widget's original `DSniang1.png` (139 x 139, RGB565A8), rows 123..262, pinned right (columns 95..234, 6 px from the right edge); idle squash breathing |
| Balance animation | The main value **rolls** to the new balance on change (600 ms tween); see below |
| Status line | Peak/valley badge, then unconfigured / connecting / online / refreshing / invalid key / network down / over budget / balance low |
| Hint line | `Long press menu · up refresh · down preview` |

Bubble sequence (the widget advances its queue on tap and closes after the last item):
**balance → today's spend → tariff → connection → closed** (closed leaves only the whale;
the next press restarts from balance).

| Input | Action |
| --- | --- |
| Home, OK short | Advance the bubble sequence (past the last item = close) |
| Home, UP/DOWN short | Previous / next item |
| Home, OK **long** | **Open the menu** (settings page) |
| Home, UP **long** | **Refresh the balance now** |
| Home, DOWN **long** | **Preview** the spend sound (the widget has a preview button per sound row) |
| Settings, UP/DOWN short | Move the selection |
| Settings, OK short | Run / toggle the selected item |
| Settings, OK **long** | Return home |
| Settings, UP **long** on `Provisioning & API key` | **Clear stored credentials** (destructive, long press required) |
| Provisioning, OK short | Retry the saved credentials |
| Provisioning, OK **long** | Close the hotspot and return home |
| Any key | Wake the screen and reset the idle timer |

### Battery readout

The top-right corner of every screen shares one battery widget (CW2017 gauge, UTL
500 mAh profile):

| Form | Display |
| --- | --- |
| Percentage | `1%..100%` integer, followed by an 18 x 11 battery icon whose fill width scales linearly with the value |
| Colour | `> 50%` green `#2ECC9B`, `20..50%` gold `#FFC93C`, `<= 20%` orange `#E8834A` — digits, fill and outline share the colour |
| Unavailable | Only `--` is shown and the icon is **hidden entirely** (a half-empty outline reads as "flat") |

Refresh: once at boot, then the main loop re-reads it every `BATTERY_REFRESH_US`; every
publish pass carries the latest value. The readout is informational only — a low battery
plays no cue and does not change the sleep policy (that stays in its own menu item).

### Character art

The home screen uses the widget's original asset `assets/img/DSniang1.png`
(610 x 610 transparent cut-out; per the widget repo's PROVENANCE notes it was
AI-generated by the widget author and hand-picked — this project reuses it
as-is, no image is generated here):

- `tools/gen_whale_img.py` crops the transparent margins then scales it to 139 x 139
  and encodes it as an **RGB565A8** C array (`assets/img/whale_dsnang_img.c`):
  139 x 139 x 2 bytes of little-endian RGB565 colour plane followed by 139 x 139
  bytes of A8 alpha, keeping full 8-bit anti-aliased edges;
- It is pinned **right** (columns 95..234, 6 px off the right edge)
  with its bottom edge at 262, leaving 4 px clear above the status line at 266 —
  the widget pins it to the bottom-right, but centred suits the portrait card
  better — and it squashes with the stage (the stage holds the art only; the
  bubble is a separate layer);
- On a spend, the coin still drops, now landing in the empty lane to the left of
  the art (`COIN_X`) instead of across the face;
- To swap or resize, rerun `tools/gen_whale_img.py --size N`; `--ascii` prints a
  brightness preview so the silhouette can be checked without flashing.
- **LVGL now allocates from the system heap** (`sdkconfig.defaults`,
  `CONFIG_LV_USE_CLIB_MALLOC=y`): with both the character art and the bubble
  image on screen, LVGL's own TLSF pool (even at 96 KB) **deadlocked** inside
  `block_locate_free` (`lv_tlsf.c`) — the main task tripped the task watchdog
  every 5 s and the UI froze. Enlarging the pool only postponed it (48 -> 96 KB
  survived one version), so the built-in pool is gone: the system heap has far
  more headroom and returns NULL instead of spinning. Remember to delete
  `build/validation-whale/sdkconfig` after changing defaults.

### Q-bounce animation (squash & stretch)

The old "gentle bobbing" is replaced by the widget's **Q-bounce**; **only the
character bounces — the bubble does not**:

- Authoritative parameters from the widget: `.dshwv-body{transform-origin:50%
  100%;transition:transform .22s cubic-bezier(.34,1.56,.64,1)}` with the pressed
  state `scaleY(.88) scaleX(1.05)`;
- One bounce = squash for 180 ms (ease-out, `scaleY -> .88`) then spring back for
  420 ms (`cubic-bezier(.34,1.56,.64,1)`, which overshoots past 1.05 before
  settling — that overshoot *is* the "Q" feel);
- `scaleX` mirrors `scaleY`: `sx - 1 = 5/12 x (1 - sy)`, matching the widget's
  `.88 <-> 1.05` pair — the flatter it gets, the wider it spreads;
- **The stage holds the character only**: `stage` is y 123..262 (240 x 139) and
  scales around the **character's foot centre** (120, 262). The bubble is a
  separate layer that does not bounce — scaling it along made the whole screen
  wobble, and the larger stage meant redrawing 240 x 234 every frame, which this
  SPI display cannot keep up with;
- **Why it was slowed down**: the widget's .22s assumes a 60 fps web page. On this
  display, 110 ms only fits two or three frames, which reads as a flicker plus
  stutter. At 180 + 420 ms (about 0.6 s) each frame moves far less and the motion
  looks continuous;
- A gentler idle breathing loop runs continuously (2.4 s half period, only down
  to `.97`); a key press stops it, plays the full bounce and restarts the
  breathing when the spring-back finishes;
- The battery readout, status row, bottom hint and the bubble layer all stay
  outside the stage and do not move.

### Bubble enter / exit

The bubble is never toggled instantly: the whole layer (bubble image + three text
rows) plays an **ease-in-out**, and both directions go through the bottom:

- Disappear: **top to bottom** — it sinks 32 px downwards while fading out, 300 ms;
- Appear: **bottom to top** — it rises from 32 px below into place while fading in
  (`opa 0 -> 255`), 340 ms;
- **Switching content** (up/down keys change the view) chains the two: the old
  bubble sinks downwards and disappears, the three rows are swapped while it is
  fully transparent, then the new one rises from below;
- The text swap lives in the disappear animation's completed callback — doing it
  earlier shows the old copy visibly flipping to the new one at half opacity;
- Closing only becomes `HIDDEN` after the sink finishes (otherwise the last frame
  is cut off); during a content switch `s_bub_shown` stays true, so the layer is
  not hidden and the enter animation takes over directly;
- Path is `lv_anim_path_ease_in_out` throughout; setting `opa` on the layer is
  enough — LVGL 9 applies opacity recursively, so image and text fade together;
- No replay when nothing changed: opening/closing only animates on a `bubble_open`
  flip, switching only on a view change (the balance refresh calls
  `whale_ui_update` every second; if neither changed it just writes the text);
- The three text rows belong to the bubble layer, so they disappear with it
  (previously they hung off the stage and left three orphan lines on screen).

Constants (`main/whale_ui.c`): `BUB_OUT_MS` 300 / `BUB_IN_MS` 340 / `BUB_SLIDE_DY` 32.

### Speech bubble

The bubble is no longer a rounded rectangle pretending to be one: it follows the
widget's bubble SVG geometry (canvas 1026 x 700, stroke `#203170` width 18) and is
rasterised into a single **RGB565A8** image (`assets/img/whale_bubble_img.c`,
generated by `tools/gen_whale_bubble.py`):

- Main ellipse: centre (454,247), rx 373 ry 232 → 194 x 120 on screen at 18..212 / 30..151;
- Tail: a half-ellipse joining the ellipse bottom to bubble 1, tilted 10;
- Bubble 1 (352,561) rx 37.5 ry 26 and bubble 2 (442,646) rx 24.5 ry 18, scaled
  with the same factor — matching the `assets/DSniang02.png` composition;
- Z-order follows the reference: the art is drawn first and the bubble sits on top
  (the widget's bubble carries `z-index:1`);
- The three text rows are laid out around the ellipse centre (row centres at 32,
  text width 140): a wide ellipse narrows towards its top and bottom, so 140 px is
  the largest width that stays inside the fill; over-long content (SSID etc.) still
  truncates with an ellipsis;
- To resize, rerun `tools/gen_whale_bubble.py --width N` and update the `BUB_IMG_*`
  / `BUB_ELL_*` constants in `whale_ui.c`; `tools/preview_whale_screen.py` renders a
  full-screen preview from the same geometry — check the picture before flashing.

### Screen timeout

`Screen timeout` sets how long the card stays awake with no key pressed. Default is
300 s; any key restarts the count.

| Step | Backlight dims | Deep sleep | Notes |
| --- | --- | --- | --- |
| Off | never | never | **Always on** — Wi-Fi stays up and the balance keeps refreshing |
| 100 s | 50 s | 100 s | |
| 300 s (default) | 150 s | 300 s | |
| 30 min | 15 min | 30 min | |

Details:

- **Dim at half time, sleep at full time.** At the halfway mark the backlight drops to
  8% as a "about to sleep" hint; any key restores full brightness and restarts the count.
- **"Off" costs battery.** No sleep means screen and Wi-Fi stay on; use it for demos or
  debugging, and go back to a finite step for everyday use.
- **Busy means no sleep.** While provisioning is showing hotspot info or a balance request
  is in flight, the timeout is held off (`s_busy` and `whale_prov_running()`).
- Waking does not change: any key wakes deep sleep, then the card reconnects and refreshes.

## Provisioning web page

Three buttons cannot type an API key, so configuration happens in a browser:

1. Settings → `Provisioning & API key` → the card opens its own hotspot
   `WhaleCard-<last two MAC bytes>`, password `12345678` (`main/whale_prov.c`);
   it scans for nearby networks on entry, so the very first page already carries a list.
2. Connect the phone or computer to that hotspot and open `http://192.168.4.1`.
3. The Wi-Fi name is a **native `<select>` dropdown**: the first entry is the
   saved network (selected by default), then scanned networks strongest first,
   each labelled `name · -48dBm · needs password / open`. Press "rescan nearby
   networks" on the page when the list goes stale.
4. Networks missing from the dropdown (hidden SSIDs) go in the "type the Wi-Fi
   name" field below — when that field is non-empty it **wins over** the
   dropdown; when neither is given the previous SSID is kept, so a key-only
   edit cannot wipe a working network.
5. Fill in the Wi-Fi password, DeepSeek API key and refresh interval.
6. The card saves and connects immediately: a chime plays, the page shows the
   IP address, and the card returns home (or press OK long to leave by hand).

Scanning details and trade-offs:

- Up to 48 raw results; duplicate SSIDs collapse to the strongest one; the top 12
  by signal reach the page.
- The scan is synchronous (`esp_wifi_scan_start(..., true)`) and runs once after
  the hotspot comes up, so the page needs no JavaScript.
- SSIDs are user text and always go through `whale_html_escape` before entering
  the HTML; otherwise `& < > " '` would break the page.
- A scan briefly pauses the STA connection. Acceptable during provisioning, and
  nothing scans once provisioning exits.
- **`<select>` rather than `<input list="...">`**: `datalist` behaves wildly
  differently across mobile browsers — iOS Safari and many in-app browsers never
  raise the suggestions, so all the user sees is an empty text field and no way
  to pick. A native `<select>` lets the system draw its own picker, which always
  opens; the price is no type-to-filter, which the extra "type the name" field
  covers. Each `<option>` label repeats the SSID itself — a label of just
  `-48dBm` is unreadable once the dropdown closes.

Common connectivity probes (`/generate_204`, `/hotspot-detect.html`, …) are
registered and redirected to the form so phones can raise the captive-portal
window. This is best effort only; nothing is hijacked.

## Data and accounting

- Source: `GET https://api.deepseek.com/user/balance` with
  `Authorization: Bearer <key>`; TLS uses the IDF root certificate bundle
  (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE`).
- Refresh interval: 30 / 60 / 120 / 300 s, default 60 s. Automatic while online,
  manual on OK short press.
- Accounting follows the open-source widget: a **drop** in balance accumulates as
  today's spend, a **rise** is recorded as a top-up and never cancels recorded
  spend; a new Beijing-time day rebuilds the baseline. The ledger lives in NVS.
- Tariff: weekdays 09:00–12:00 and 14:00–18:00 are peak, everything else is
  off-peak; weekends are off-peak all day.
- Time comes from SNTP after connecting (`CST-8`). If sync fails, the tariff row
  says the time is not synced while the balance keeps working.

### Balance roll animation

The widget rolls the number when the balance changes. There is no per-digit
reel widget on the card, so this approximates it with a **value tween**: every
frame re-renders the current value as `¥x.xx`, moving the integer and both
decimals together, easing out over 600 ms.

Limits worth knowing:

- **No roll on the first balance** — going from "none" to "has one" has no
  starting point; same after a reconnect that dropped the balance.
- **Switching to another bubble view stops the roll immediately** — that line
  belongs to the other view, and a running tween would overwrite it.
- **Above roughly ¥21.47 M it just lands** — `lv_anim` values are `int32`, so the
  range is checked before tweening.
- The completed callback paints the final frame: the last tween frame is not
  guaranteed to land exactly on the target, and being one cent off is worse than
  not animating.

### Tariff display styles

One tariff decision, several ways to name it — mirroring the widget's peak module
"display style" dropdown (`BUBBLE_PEAK_STYLE_OPTS`). Settings → `Tariff style`,
OK short press cycles:

The exact Chinese strings live in `whale_peak_style_name()` /
`whale_peak_status_text()` (`main/whale_model.c`); the table below spells them out
in pinyin so this file stays readable without a CJK font.

| Style | Peak reads | Off-peak reads | Bubble label |
| --- | --- | --- | --- |
| Default | "gao feng shi duan" (peak hours) | "kong xian shi duan" (idle hours) | "feng gu shi duan" |
| Liangwen | "Liang Wen Feng" | "Liang Wen Gu" | "feng gu shi duan" |
| !?Qiang?! | "!?feng feng?!" | "!?gu gu?!" | "feng gu shi duan" |
| Countdown | — | — | "shi duan dao ji shi" |
| Terse | "feng" | "gu" | "feng gu shi duan" |

"Liangwen" is a pun on the founder's name crossed with the peak/valley
characters, and "Qiang" doubles the peak/valley character inside exclamation
marks — both are in-jokes carried over from the upstream widget.

Countdown is the odd one out: the main value becomes the countdown itself
(`H:MM`, or `--:--` when the day has no further switch) and the hint line names
the next period — the widget's standalone "period countdown" module. Every other
style keeps the countdown on the hint line.

The peak/valley badge on the status line does **not** follow the style (it always
reads "feng shi" / "gu shi"): the slot is only 44 px wide, and a four-character
label such as "kong xian shi duan" would push the status text out.

## Sounds

`main/whale_tone.c` synthesizes 16 kHz mono PCM from a phase accumulator, a
256-point sine table and a per-note envelope. The timbres come from the widget's
`assets/*.wav|mp3`: `tools/analyze_wav.py` (standard library only) measures the
original RMS envelope and zero-crossing track, which then becomes a note table.
The widget plays sampled audio while the card synthesizes, so these are
**same-family approximations, not sample-accurate copies**.

| Cue | Trigger | Shape |
| --- | --- | --- |
| Press "ya" | Short press on home / any long press | Square 560→1240→900 Hz slide, ~0.16 s (widget `Ya1.mp3`) |
| Release | Reserved | Square 900→520 Hz slide, ~0.12 s (widget `Ya2.mp3`) |
| Coin drop | Balance decreased (spend detected) | Square B5 → E6 with fast decay, ~0.49 s |
| Experience orb | Preview / task end | Three square plucks 1760/2349/3136 Hz, ~0.29 s (`minecraft-exp-orb.wav`) |
| Bell A | Preview / task end | Sine E6 attack → B5 long tail, ~0.37 s (`task-end-a.wav`) |
| Connected | Wi-Fi got an IP | Sine C5-E5-G5-C6 arpeggio, ~0.54 s |
| Tick | Settings navigation | Single short tone |
| Warning | Budget hit / balance below the warning line | Two equal 880 Hz beeps, ~0.28 s |
| Low cue | Manual refresh failed | Two descending low tones |

Every cue goes through the single `play_sound()` gate in `main.c`, so the master
sound switch silences all of them.

## Chinese fonts

- Source font: Noto Sans CJK SC Regular (SIL OFL 1.1).
- Generate: `python3 tools/gen_whale_font.py` — it scans the string literals of
  `main/whale_ui.c` **and** `main/whale_model.c` (the tariff-style copy lives in
  the model layer so host tests can assert it) and emits
  `assets/fonts/whale_ui_font_16.c` and `whale_ui_font_24.c`.
- Gate: `tools/check_whale_font_coverage.py` decodes the generated cmap tables and
  checks the inventory plus every literal used by the UI, then validates CJK
  glyph metrics. It runs inside `tools/validate.sh`.
- Dynamic text (SSID, IP, time) is rendered as an ASCII preview
  (`whale_text_ascii_preview`): the device font is a subset of the fixed UI copy
  and cannot cover arbitrary Han characters. That is a deliberate contract, not a
  silent fallback.
