# 2048

An offline 2048 game for the FoloToy AI Passport. It boots straight into a
match — there is no test menu — and plays entirely with the three physical keys.

## Screens and controls

Portrait 240 x 320. Everything is drawn by the application itself
(`main/g2048_ui.c`); the baseline demo menu and its pixel shell are not reused.

| Area | Content |
| --- | --- |
| Title bar | `2048` on the left, live battery percentage on the right (`--` when unavailable) |
| Info panels | Current score, and the largest tile on the board |
| Board | 4 x 4 grid, 164 x 164 px, 36 px cells with a colour ramp per value |
| Hint line | How to pick a direction and slide |
| Direction wheel | Four chips in compass order: up, right, down, left; the selected one is highlighted |
| Hint line | How to restart |
| Result overlay | Drawn over the board when no move is left |

Key mapping:

| Input | Action |
| --- | --- |
| UP short press | Move the wheel selection back one step |
| DOWN short press | Move the wheel selection forward one step |
| OK short press | Slide in the highlighted direction |
| OK long press | Start a new game |
| Any key | Wake the screen and reset the idle timer |
| OK short press (game over) | Start another game |

Sliding in a direction that cannot move anything changes nothing and plays a
short low cue; it does not spawn a tile and does not count as a move.

## Acceptance scenarios

| Case | Setup and input | Expected result |
| --- | --- | --- |
| Boot | Power on, or reset | The board appears directly; a saved match is restored when one exists |
| Direction selection | Repeatedly short-press UP and DOWN | The highlight walks up, right, down, left and wraps; the board does not change |
| Slide | Select a direction, short-press OK | Tiles slide and merge, score grows, exactly one new tile appears |
| Blocked slide | Select a direction with no legal move | No change on the board, a short low cue plays |
| Merge feedback | Cause a merge | The merged cells flash a bright border and pop once |
| Reach 2048 | Merge into 2048 | A congratulation banner shows for about two seconds and play continues |
| Game over | Fill the board with no legal move | The result overlay shows the score; OK starts another game |
| Restart | Hold OK during play | A new game starts immediately |
| Persistence | Play a few moves, then power off and on | The same board, score and move count come back |
| Idle | Leave the device alone | Backlight dims at 45 s; at 120 s the device sleeps, any key wakes it |

## Design notes

- **Model.** `main/g2048_model.c` holds the whole rule set — board, sliding,
  merging, scoring, spawning, game-over detection and serialization — with no
  ESP-IDF or LVGL dependency, so it is covered by the host test
  `tests/test_g2048_model.c`.
- **Determinism.** The spawn generator is a xorshift32 state stored with the
  board, so a restored match continues the same sequence.
- **Persistence.** A 56-byte little-endian blob in NVS, written after every
  accepted move. It carries a magic word and version, and invalid tiles or a
  wrong length are rejected instead of being drawn.
- **Audio.** Four cues are synthesized as square waves in a worker task
  (`main/g2048_audio.c`); no audio files are stored. Missing codec is degraded
  to silent play.
- **Power.** Idle dims the backlight to 8% after 45 s and enters deep sleep after
  120 s. Sleep is skipped while a key is held, and the documented peripheral
  shutdown order is followed before `esp_deep_sleep_start()`.
- **Fonts.** Chinese text uses a purpose-built Noto Sans CJK subset at
  `assets/fonts/game2048_font_16.c`; see the [asset notes](../../../assets/README.md#fontsgame2048_font_16c).
  `tools/check_app_font_coverage.py` gates coverage and glyph metrics in the
  static gate. Tile numbers use Montserrat 24/20/14 by digit count.

## Build and validate

Run from the repository root with ESP-IDF 5.5.3 active:

```bash
./tools/validate.sh --static    # repository checks + host tests + font coverage
./tools/validate.sh --firmware  # firmware build + merged-image verification
./tools/validate.sh             # complete gate
```

The deliverable is the merged image `build/FoloToy-AI-Passport-full.bin`,
written from offset `0x0`:

```bash
python -m esptool --chip esp32c3 -p <port> -b 460800 \
    write-flash 0x0 build/FoloToy-AI-Passport-full.bin
```

Flashing requires explicit approval; a build is not hardware validation.
