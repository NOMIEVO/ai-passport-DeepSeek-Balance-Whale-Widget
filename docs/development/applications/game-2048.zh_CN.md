# 2048

FoloToy AI Passport 上的离线 2048。开机直接进入对局——没有测试菜单——全程用
三个物理按键操作。

## 页面与操作

竖屏 240 × 320。界面全部由应用自己绘制（`main/g2048_ui.c`），不复用基线 demo
的测试菜单与像素外壳。

| 区域 | 内容 |
| --- | --- |
| 标题栏 | 左侧 `2048`，右侧实时电量百分比（读不到时显示 `--`） |
| 信息板 | 当前分数、棋盘上的最大方块 |
| 棋盘 | 4 × 4，164 × 164 px，格子 36 px，按数值配色 |
| 提示行 | 如何选方向并滑动 |
| 方向轮盘 | 按罗盘顺序排四个键位：上、右、下、左，当前选中项高亮 |
| 提示行 | 如何重开 |
| 结算浮层 | 无路可走时盖在棋盘上 |

按键映射：

| 输入 | 动作 |
| --- | --- |
| 上 短按 | 轮盘选择回退一格 |
| 下 短按 | 轮盘选择前进一格 |
| 确定 短按 | 朝高亮方向滑动 |
| 确定 长按 | 重新开始一局 |
| 任意键 | 点亮屏幕并重置空闲计时 |
| 确定 短按（结束后） | 再来一局 |

朝一个动不了的方向滑动不会改变棋盘，只播放一声短促低音；不会生成新方块，
也不计入步数。

## 验收场景

| 场景 | 前置与输入 | 预期结果 |
| --- | --- | --- |
| 开机 | 上电或复位 | 直接进入棋盘；有存档时恢复上次局面 |
| 选方向 | 反复短按上/下 | 高亮按上→右→下→左循环，棋盘不变 |
| 滑动 | 选中方向后短按确定 | 方块滑动合并，分数增加，只生成一个新方块 |
| 无效滑动 | 选一个动不了的方向 | 棋盘不变，播放短促低音 |
| 合并反馈 | 制造一次合并 | 合并格描亮边并弹一下 |
| 达成 2048 | 合成 2048 | 弹出祝贺提示约两秒，游戏继续 |
| 结束 | 填满且无法移动 | 浮层显示得分，确定键再来一局 |
| 重开 | 游戏中长按确定 | 立即开新局 |
| 掉电续玩 | 走几步后断电再上电 | 棋盘、分数、步数原样恢复 |
| 空闲 | 静置不动 | 45 秒调暗背光；120 秒深度睡眠，任意键唤醒 |

## 设计要点

- **模型。** `main/g2048_model.c` 承载全部规则——棋盘、滑动、合并、计分、生成、
  结束判定与序列化，不依赖 ESP-IDF 和 LVGL，因此由主机测试
  `tests/test_g2048_model.c` 覆盖。
- **可复现。** 生成新方块用的是 xorshift32，状态随棋盘一起存档，续玩时随机序列
  接着走。
- **存档。** NVS 里存 56 字节小端块，每次有效移动后写入。带魔数与版本号，
  长度不对或方块值非法一律拒收，不会把脏数据画到屏幕上。
- **音效。** 四种提示音由方波合成，放在 worker 任务里播放
  （`main/g2048_audio.c`），不占 Flash 存音频文件；codec 不可用时降级为静音。
- **功耗。** 空闲 45 秒把背光调到 8%，120 秒进入深度睡眠。按键被按住时拒绝入睡，
  `esp_deep_sleep_start()` 之前按文档顺序逐个关闭外设。
- **字库。** 中文用自建的 Noto Sans CJK 子集
  `assets/fonts/game2048_font_16.c`，见[资源说明](../../../assets/README.zh_CN.md)。
  `tools/check_app_font_coverage.py` 在静态门禁里检查覆盖与字形度量。
  棋盘数字按位数分别用 Montserrat 24/20/14。

## 构建与校验

在仓库根目录、ESP-IDF 5.5.3 已激活的环境下：

```bash
./tools/validate.sh --static    # 仓库检查 + 主机测试 + 字体覆盖
./tools/validate.sh --firmware  # 固件构建 + 合并镜像校验
./tools/validate.sh             # 完整门禁
```

交付物是可从 `0x0` 刷写的合并镜像 `build/FoloToy-AI-Passport-full.bin`：

```bash
python -m esptool --chip esp32c3 -p <port> -b 460800 \
    write-flash 0x0 build/FoloToy-AI-Passport-full.bin
```

刷机必须经明确授权；构建成功不等于硬件验证通过。
